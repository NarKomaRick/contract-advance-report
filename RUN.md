# Запуск тестовой версии

Этот файл объясняет запуск, чтение результата и проверку программы.
Назначение каждого файла и связи между модулями описаны в [FILES.md](FILES.md).

Программа строит отчёт на дату по трём исходным CSV. Нужен Python 3.10 или новее.
Для запуска отчёта внешние библиотеки не нужны. Команды ниже выполняются из папки проекта.

```powershell
python report.py --data-dir data --date 2026-11-10
```

Результат: `reports/2026-11-10/works.csv` и `reports/2026-11-10/contracts.csv`.
Для другого места сохранения:

```powershell
python report.py --data-dir data --date 2026-11-10 --output reports/check-2026-11-10
python report.py --help
```

Папка результата должна быть новой. Повторный запуск в существующую папку завершается
ошибкой: выберите другое значение `--output`. Программа не перезаписывает исходные данные
или предыдущие отчёты. Оба CSV сначала готовятся во временной папке рядом с результатом,
затем публикуются вместе переименованием новой папки.

Дата обязательна, формат строго `YYYY-MM-DD`, день включается целиком.
Пути без абсолютного адреса считаются относительно текущей рабочей папки.
Код завершения: 0 при успехе, 1 при ошибке данных или файлов, 2 при ошибке аргументов CLI.
Сообщения об ошибках идут в stderr, успешная сводка в stdout.

## Как читать результат

CSV имеют русские заголовки, кодировку UTF-8 с BOM, разделитель запятую и десятичную точку.
При импорте в Excel или другую таблицу выберите эти настройки. Поля с запятыми заключаются
в кавычки стандартными средствами CSV. Денежные значения записываются с двумя знаками копеек.
В каждой строке есть дата отчёта.

В `works.csv`:

- «Цена» сохраняет исходную цену, в том числе для отменённых работ.
- «Обязательство по работе» равно цене для неотменённых работ и нулю для отменённых.
- «Прямые платежи» показывают чистую оплату с указанным work_id.
- «Распределено общих платежей» показывает условно отнесённую долю общих платежей.
- «Выплачено» равно сумме этих двух колонок. Это расчётное распределение, а не подтверждённое назначение всех платежей.
- «Осталось оплатить» равно максимуму из нуля и разности обязательства и оплаты.
- «Переплата» показывает оплату сверх обязательства, включая прямые платежи по отменённым работам.

Остаток включает запланированные работы и не означает просроченный долг за принятые работы.
Статус «Принята» позволяет отдельно увидеть уже выполненные работы.

В `contracts.csv` перечисления и возвраты показаны отдельно. «Выплачено за вычетом возвратов»
равно «Отнесено на работы» плюс «Нераспределённый аванс».
«Ожидает перечисления» включает платежи, созданные к дате, но ещё не перечисленные.
Они не входят в оплату и не распределяются.

«Осталось оплатить по работам» суммирует положительные остатки отдельных работ.
«Переплаты по работам» не переносятся автоматически на другие работы.
«Баланс до суммы договора» равен сумме договора минус чистые платежи.
«Баланс до цены неотменённых работ» равен цене неотменённых работ минус чистые платежи.
Эти два баланса могут быть отрицательными и не равны автоматически сумме остатков по работам.
В «Примечаниях» показаны отмены, расхождения сумм, переплаты и свободный аванс.

## Тесты

Для тестов используется pytest, отдельно от зависимостей запуска программы.
Можно создать окружение без изменения глобально установленных пакетов:

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m pytest -q
```

Если pytest уже установлен: `python -m pytest -q`.
Тесты работают с временными копиями CSV и не изменяют исходную папку `data/`.
Покрываются контрольные суммы, исторические статусы, возвраты, отмены, прямые переплаты,
округление, независимость от порядка строк, ошибки входных данных и полный запуск CLI.
Генератор с фиксированным seed дополнительно проверяет сохранение денег и ограничения
распределения на 200 наборах входов. Hypothesis для этого не требуется.

## Устройство

- `models.py`: структуры данных, деньги в целых копейках.
- `csv_io.py`: проверка и чтение исходных CSV, форматирование и запись результата.
- `calculation.py`: чистые функции восстановления состояния на дату и распределения.
- `report.py`: параметры запуска, сводка, обработка ошибок.
- `tests/test_report.py`: независимые проверки через pytest.

Расчёт группирует работы и платежи по договорам. Сортировка нужна для стабильного порядка
строк и распределения остатков копеек. Полного перебора всех платежей для каждой работы нет.

## Ограничения тестовой версии и сдача

Правила, требующие подтверждения бухгалтера, описаны в `DECISIONS.md`.
Короткая записка находится в `ACCOUNTANT_NOTE.md`.
Известные цены и состав работ используются с даты подписания договора: история их изменения
и даты создания работ отсутствуют. Реальная задолженность по срокам оплаты не рассчитывается,
поскольку графиков платежей и условий наступления оплаты нет.

Реализация подготовлена в Codex. Требуемый условием полный экспорт Claude Code через `/export`
не создан и не подменяется этим документом. Перед сдачей этот пункт остаётся невыполненным.
Исходное условие в `README.md` и данные сохранены. Ничего не публикуется автоматически.
