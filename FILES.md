# Карта файлов проекта

Здесь описано, за что отвечает каждый файл репозитория и в каком порядке их читать.
Начните с исходного условия в `README.md`, затем откройте `RUN.md` для запуска
и `DECISIONS.md` для понимания правил расчёта.

| Файл | За что отвечает |
|---|---|
| [README.md](README.md) | Исходное условие тестового задания: контекст, требования к отчёту и состав сдачи. Сохранено без изменений. |
| [FILES.md](FILES.md) | Эта карта: объясняет назначение всех файлов и путь данных через программу. |
| [RUN.md](RUN.md) | Инструкция запуска и тестирования, описание колонок результата, контрольные суммы и ограничения версии. |
| [DECISIONS.md](DECISIONS.md) | Допущения и выбранные правила: как распределять авансы, учитывать отмены, возвраты, материалы и копейки. Для каждого решения указаны альтернативы и последствия ошибки. |
| [ACCOUNTANT_NOTE.md](ACCOUNTANT_NOTE.md) | Короткая записка бухгалтеру простым языком: как читать отчёт и какие допущения подтвердить. |
| [report.py](report.py) | Исполняемый CLI. Принимает папку данных, дату и папку результата, связывает остальные модули, печатает сводку и ошибки. Запускается пользователем. |
| [models.py](models.py) | Общие структуры данных: договор, работа, платёж, выгрузка и строки отчёта. Денежные значения хранятся в целых копейках. Здесь нет чтения файлов или распределения денег. |
| [csv_io.py](csv_io.py) | Читает три исходных CSV, проверяет формат и связи, преобразует суммы и даты. Записывает результат с русскими заголовками, не перезаписывая существующую папку. |
| [calculation.py](calculation.py) | Правила расчёта: состояние на дату, вычет возвратов, прямые платежи, пропорциональное распределение, остатки и итоги. Работает со структурами данных и не обращается к файлам. |
| [requirements-dev.txt](requirements-dev.txt) | Список зависимостей для разработки и тестов: pytest. Для обычного запуска отчёта установка этих пакетов не нужна. |
| [.gitignore](.gitignore) | Исключает из Git кэши Python и pytest, виртуальное окружение и локальные отчёты из `reports/`. |
| [tests/test_report.py](tests/test_report.py) | Автоматические проверки расчётов и полного CLI. Использует временные копии данных, проверяет контрольные суммы, даты, округление, ошибки и защиту от перезаписи. |
| [data/README.md](data/README.md) | Поясняет роль входных файлов, связи между ними и отличие выгрузки от результата отчёта. |
| [data/FORMAT.md](data/FORMAT.md) | Исходное описание колонок входных CSV и допустимых статусов. Сохранено без изменений. |
| [data/contracts.csv](data/contracts.csv) | Входные договоры: идентификатор, подрядчик, сумма и дата подписания. Определяет исходную сумму договора. |
| [data/works.csv](data/works.csv) | Входные работы: связь с договором, название, цена, текущий статус и даты приёмки или отмены. |
| [data/payments.csv](data/payments.csv) | Входные платежи: сумма, договор, необязательная работа, назначение, статус и даты создания, перечисления, возврата. |
| [examples/README.md](examples/README.md) | Объясняет происхождение проверочного примера и способ его повторного расчёта. |

| [examples/2026-11-10/contracts.csv](examples/2026-11-10/contracts.csv) | Готовый пример итогов по договорам на ту же дату: перечисления, возвраты, аванс, остатки, балансы и примечания. |

## Как связаны модули

1. Пользователь запускает `report.py` с датой отчёта.
2. `csv_io.py` читает `data/contracts.csv`, `data/works.csv` и `data/payments.csv`.
3. Проверенные записи собираются в структуры из `models.py`.
4. `calculation.py` строит состояние на дату и распределяет деньги.
5. `csv_io.py` сохраняет рассчитанные строки в новую папку результата.
6. `report.py` печатает краткую сводку, а `tests/test_report.py` проверяет эти этапы.

Имена входных и выходных CSV совпадают, но назначение разное: `data/` является источником,
`examples/` содержит сохранённый пример, `reports/` предназначена для новых запусков.
В CSV не добавлены строки комментариев: они нарушили бы табличный формат и загрузку.

## Локальные служебные папки

- `reports/` содержит создаваемые пользователем отчёты и не загружается в Git.
- `__pycache__/` и `.pytest_cache/` создаются Python и pytest автоматически.
- `.venv/`, если создана, содержит локальное окружение для тестов.
- `.git/` хранит историю Git и настройки связи с приватным репозиторием.

Эти папки не являются входными данными и не нужны для чтения исходного кода.
